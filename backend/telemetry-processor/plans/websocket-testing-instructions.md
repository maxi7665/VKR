# Инструкции для ручного тестирования WebSocket с keyspace notifications

## Предварительные требования
1. Redis/Valkey с включенными keyspace notifications (`KEgx`)
2. Запущенное приложение telemetry-processor
3. WebSocket клиент (например, `websocat`, браузер с DevTools, или Postman)

## Шаг 1: Проверка конфигурации Redis
Убедитесь, что Redis настроен с keyspace notifications:
```bash
redis-cli config get notify-keyspace-events
```
Должно вернуть: `notify-keyspace-events KEgx`

## Шаг 2: Запуск приложения
```bash
./gradlew bootRun
```
Приложение должно запуститься на порту 8081.

## Шаг 3: Подписка на полигон через WebSocket

### Используя websocat:
```bash
websocat ws://localhost:8081/ws/telemetry
```

Отправьте сообщение для подписки:
```json
{
  "type": "subscribe_polygon",
  "points": [
    {"lat": 55.7558, "lon": 37.6173},
    {"lat": 55.7558, "lon": 37.6273},
    {"lat": 55.7658, "lon": 37.6273},
    {"lat": 55.7658, "lon": 37.6173}
  ]
}
```

### Ожидаемый ответ:
```json
{"type": "subscription_ack", "cellCount": X, "deviceCount": Y}
```
+ начальные данные для устройств в полигоне (если есть)

## Шаг 4: Генерация тестовых данных
Отправьте телеметрию через Kafka или напрямую в Redis:

### Вариант 1: Через Redis CLI
```bash
# Установите данные телеметрии (это вызовет keyspace notification)
redis-cli set nav:123:last '{"deviceId":123,"vehicleId":1,"latitude":55.7560,"longitude":37.6175,"s2Cell":1001,"azimuth":90,"packetTime":"2024-01-01T12:00:00"}'

# Добавьте устройство в ячейку для начальной загрузки
redis-cli sadd cell:1001:devices 123
```

### Вариант 2: Через Kafka (если настроено)
Используйте существующий пайплайн отправки телеметрии.

## Шаг 5: Проверка real-time обновлений
1. Подпишитесь на полигон, который включает ячейку 1001
2. Обновите данные устройства 123 через Redis:
```bash
redis-cli set nav:123:last '{"deviceId":123,"vehicleId":1,"latitude":55.7565,"longitude":37.6180,"s2Cell":1001,"azimuth":180,"packetTime":"2024-01-01T12:01:00"}'
```

3. WebSocket клиент должен получить обновление в реальном времени.

## Шаг 6: Тестирование фильтрации по s2Cell

### Сценарий 1: Устройство в подписанной ячейке
1. Подпишитесь на ячейку 1001
2. Обновите данные устройства в ячейке 1001
3. **Ожидаем:** Получение обновления

### Сценарий 2: Устройство вне подписанной ячейки
1. Подпишитесь только на ячейку 1001
2. Обновите данные устройства в ячейке 1002
3. **Ожидаем:** Нет обновления

### Сценарий 3: Перемещение между ячейками
1. Подпишитесь на ячейки 1001 и 1002
2. Обновите данные устройства, переместив его из 1001 в 1002
3. **Ожидаем:** Получение обновления (так как подписаны на обе ячейки)

## Шаг 7: Проверка множественных клиентов
1. Откройте два WebSocket соединения
2. Подпишите каждый на разные полигоны
3. Обновите данные устройства
4. Проверьте, что каждый клиент получает обновления только для своих подписанных ячеек

## Шаг 8: Мониторинг логов
Следите за логами приложения:
```
# Логи TelemetryWebSocketHandler
"Polygon covering X cells for session Y"
"Received Redis keyspace notification on pattern __keyevent@0__:set: nav:123:last"
"Sending update to N sessions for device 123 in cell 1001"

# Логи S2RegionTelemetryProcessor  
"loaded X cell's devices"
```

## Шаг 9: Тестирование отказоустойчивости

### Переподключение клиента:
1. Закройте WebSocket соединение
2. Откройте новое соединение
3. Подпишитесь на тот же полигон
4. Проверьте, что получаете начальные данные

### Перезапуск Redis:
1. Остановите Redis
2. WebSocket соединения должны остаться открытыми
3. Запустите Redis
4. Новые обновления должны обрабатываться

## Шаг 10: Проверка производительности

### Нагрузочное тестирование:
1. Создайте 100+ подписок
2. Генерируйте 1000+ обновлений в секунду
3. Мониторьте:
   - Загрузку CPU
   - Память
   - Задержку доставки сообщений
   - Количество keyspace notifications

## Ожидаемые проблемы и решения

### Проблема 1: Нет keyspace notifications
**Решение:** Проверьте конфигурацию Redis и перезапустите с `--notify-keyspace-events KEgx`

### Проблема 2: WebSocket не получает обновления
**Решение:**
1. Проверьте, что устройство находится в подписанной ячейке
2. Проверьте логи на наличие ошибок
3. Убедитесь, что Redis операция `set` выполнена успешно

### Проблема 3: Высокая задержка
**Решение:**
1. Увеличьте ресурсы Redis
2. Рассмотрите использование кластера Redis
3. Оптимизируйте фильтрацию на стороне приложения

## Инструменты для тестирования

### 1. websocat (командная строка)
```bash
# Установка (Linux/Mac)
cargo install websocat

# Использование
websocat ws://localhost:8081/ws/telemetry
```

### 2. Postman (GUI)
- Создайте новый WebSocket запрос
- URL: `ws://localhost:8081/ws/telemetry`
- Отправляйте JSON сообщения

### 3. Chrome DevTools
- Откройте Console
- Выполните:
```javascript
const ws = new WebSocket('ws://localhost:8081/ws/telemetry');
ws.onmessage = (event) => console.log('Received:', event.data);
ws.onopen = () => ws.send(JSON.stringify({
  type: "subscribe_polygon",
  points: [
    {"lat": 55.7558, "lon": 37.6173},
    {"lat": 55.7558, "lon": 37.6273},
    {"lat": 55.7658, "lon": 37.6273}
  ]
}));
```

## Критерии успешного тестирования
1. Клиенты получают начальные данные при подписке
2. Real-time обновления доставляются с задержкой < 100мс
3. Фильтрация по s2Cell работает корректно
4. Множественные клиенты работают изолированно
5. Система устойчива к переподключениям
6. Производительность соответствует требованиям
